Comandos remotos

Um comando depois do endereço roda no servidor e volta. O segredo está nas aspas: elas decidem quem expande o quê.

Você vai aprender
  • Rodar um comando remoto e trazer a saída.
  • Usar aspas para o comando chegar intacto.
  • Pipes, redirecionamento e o -t.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: um comando, sem entrar

Muitas vezes você só quer uma resposta do servidor. Ponha o comando depois do endereço: o ssh conecta, roda, mostra a saída e volta. Daqui em diante, o notebook da Ana já tem chave SSH instalada no servidor, então não aparece a pergunta da senha.

$ ssh lab@servidor hostname
servidor
$ ssh lab@servidor ls
relatorio.txt
site
$ ssh lab@servidor cat relatorio.txt
Relatório mensal
vendas: 42
clientes novos: 7
$

1. As aspas: quem expande o quê

O Bash do notebook lê o comando antes do ssh. Sem aspas simples, ele troca $HOSTNAME pelo nome do notebook antes de mandar. Com aspas simples, o texto vai intacto e quem expande é o Bash do servidor:

$ ssh lab@servidor echo $HOSTNAME
notebook   « expandido no notebook!
$ ssh lab@servidor 'echo $HOSTNAME'
servidor   « expandido no servidor
$
Regra prática

Ponha o comando remoto entre aspas simples. Assim ele chega ao servidor exatamente como você escreveu.

2. Pipes dos dois lados

Um | fora das aspas roda no notebook, com a saída que veio do servidor. Dentro das aspas, roda no servidor. O resultado é o mesmo; muda onde o trabalho acontece:

$ ssh lab@servidor 'cat relatorio.txt' | grep vendas
vendas: 42
$ ssh lab@servidor 'grep vendas relatorio.txt'
vendas: 42
$ ssh lab@servidor 'cat relatorio.txt' > copia.txt
$ cat copia.txt
Relatório mensal
vendas: 42
clientes novos: 7
$

O > copia.txt fora das aspas gravou a saída do servidor num arquivo do notebook: um jeito simples de trazer um arquivo de texto.

3. O código de saída e o terminal

O ssh devolve o código de saída do comando remoto, então dá para usar em scripts com && e if:

$ ssh lab@servidor 'ls naoexiste'; echo "código: $?"
ls: não foi possível acessar 'naoexiste': Arquivo ou diretório inexistente
código: 2
$

Um comando remoto não ganha um terminal de verdade (um “tty”). Programas de tela cheia, como top ou nano, precisam de um: peça com -t.

$ ssh lab@servidor tty
não é um tty   « sem -t, não há terminal
$ ssh -t lab@servidor tty
/dev/pts/1   « com -t, há
Connection to servidor closed.
$

Quando dá errado

Esqueci as aspas no &&

Sem aspas, o && é do Bash do notebook: só o cd foi para o servidor, e o pwd rodou no notebook:

$ ssh lab@servidor cd /etc && pwd
/home/ana
$

Com aspas, ssh lab@servidor 'cd /etc && pwd' roda os dois no servidor e mostra /etc.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: faça o servidor dizer o próprio nome, com a variável $HOSTNAME expandida lá.



ssh lab@servidor 'echo "remoto: $HOSTNAME"'

remoto: servidor

Missão: rode um ls de um arquivo que não existe no servidor e mostre o código de saída que o ssh devolveu.



ssh lab@servidor 'ls naoexiste'; echo "código: $?"

ls: não foi possível acessar 'naoexiste': Arquivo ou diretório inexistente
código: 2

Resumo

  • Aspas simples: o comando chega intacto.
  • Fora das aspas, pipes e > são do notebook.
  • -t para programas de tela cheia.
