Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

Os dois erros de chave mais comuns

Esta aula junta os erros de autenticação que você mais vai ver, o que cada um quer dizer e como resolver.

1. Permission denied (publickey)

O servidor só aceita chave (senha desligada) e nenhuma das chaves que o notebook ofereceu está no authorized_keys dele:

$ ssh lab@servidor
lab@servidor: Permission denied (publickey).   « só chave, e nenhuma serviu
$ ssh -v lab@servidor true 2>&1 | grep -E 'Offering|Permission denied'
debug1: Offering public key: /home/ana/.ssh/id_ed25519 ED25519 SHA256:1wgPtPehvxJHxq1qIDo4s7Eu1nZObhihxhAUBwbUHkU
lab@servidor: Permission denied (publickey).
$
No ssh -vCausa provável
Ofereceu a chave e não foi aceitafalta a chave pública no ~/.ssh/authorized_keys do servidor, ou o usuário está errado.
Não ofereceu chave nenhumao nome do arquivo não é o padrão: use -i ou IdentityFile.
O log do servidor fala em <code>bad ownership</code>permissões da pasta do usuário no servidor (aula de permissões).

Com a senha desligada, o ssh-copy-id não funciona mais: a chave nova entra por outro caminho que já tem acesso (outra chave, o console do provedor, um colega).

2. UNPROTECTED PRIVATE KEY FILE

A chave privada ficou legível por outros usuários (aqui, 644). O ssh se recusa a usá-la:

$ ls -l ~/.ssh/id_ed25519
-rw-r--r-- 1 ana ana 399 nov 21 12:03 /home/ana/.ssh/id_ed25519   « todo mundo lê: ruim
$ ssh -o BatchMode=yes lab@servidor hostname
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @   « o aviso
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for '/home/ana/.ssh/id_ed25519' are too open.
It is required that your private key files are NOT accessible by others.
This private key will be ignored.
Load key "/home/ana/.ssh/id_ed25519": bad permissions   « a chave foi ignorada
lab@servidor: Permission denied (publickey,password).
$ chmod 600 ~/.ssh/id_ed25519
$ ssh lab@servidor hostname
servidor
$

Quando dá errado

Usuário errado

A chave está certa, mas no usuário errado do servidor. A ana não tem conta lá com essa chave:

$ ssh -o BatchMode=yes ana@servidor hostname
ana@servidor: Permission denied (publickey,password).
$

Confira o usuário antes do @ (ou o User no config). Sem usuário, o ssh usa o seu nome do notebook.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: a sua chave privada ficou com permissões abertas. Arrume e conecte.



chmod 600 ~/.ssh/id_ed25519 && ssh lab@servidor hostname

servidor

Missão: com uma chave que o servidor não conhece, tente entrar sem perguntar senha.



ssh -o BatchMode=yes lab@servidor hostname

lab@servidor: Permission denied (publickey,password).

Resumo

  • Veja com -v que chave foi oferecida.
  • Chave privada: 600.
  • Confira o usuário.
