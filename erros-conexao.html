Erros de conexão

Antes da chave e da senha, a conexão precisa chegar. A mensagem diz onde parou.

Você vai aprender
  • Diferenciar os erros de rede.
  • Usar ConnectTimeout.
  • Ver se a rede está boa com -v.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

Antes da senha e da chave: a rede

Estes erros acontecem antes de qualquer autenticação. A mensagem diz em que passo parou:

MensagemOnde parou
Could not resolve hostnameo nome não virou IP: erro de digitação ou DNS.
Connection refusedo computador respondeu, mas ninguém atende nessa porta.
Connection timed outninguém respondeu: IP errado, firewall descartando ou máquina desligada.
No route to host / Network is unreachableo notebook não tem caminho até esse IP.

1. Nome errado

$ ssh lab@servidr
ssh: Could not resolve hostname servidr: Temporary failure in name resolution   « o nome não existe
$

2. Porta errada ou sshd parado

$ ssh -p 2222 lab@servidor
ssh: connect to host servidor port 2222: Connection refused   « nada na porta 2222
$

A mesma mensagem, na porta certa, quando o sshd está parado (na coleta, paramos de propósito):

$ ssh lab@servidor
ssh: connect to host servidor port 22: Connection refused   « o servidor está lá, o sshd não
$

No servidor: sudo systemctl status ssh e sudo systemctl start ssh.

3. Ninguém responde

Um IP da rede em que não há máquina nenhuma. O ConnectTimeout evita esperar mais de um minuto:

$ ssh -o ConnectTimeout=5 lab@192.168.0.50
ssh: connect to host 192.168.0.50 port 22: No route to host
$

Quando dá errado

Testando só a porta

Para saber se a porta abre, sem entrar, o -v com true mostra o primeiro passo. Conectou e deu outro erro depois? Então a rede está boa:

$ ssh -v -o BatchMode=yes lab@servidor true 2>&1 | grep -E 'Connecting to|Connection established|Permission denied'
debug1: Connecting to servidor [192.168.0.20] port 22.
debug1: Connection established.
lab@servidor: Permission denied (publickey).
$

Aqui a conexão foi estabelecida: o problema não é a rede, é a chave.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: tente conectar numa porta em que nada escuta.



ssh -p 2222 lab@servidor

ssh: connect to host servidor port 2222: Connection refused

Missão: erre o nome do servidor de propósito.



ssh lab@servidr

ssh: Could not resolve hostname servidr: Temporary failure in name resolution

Resumo

  • Leia a mensagem: ela diz o passo.
  • Connection refused: sshd parado ou porta errada.
  • Conectou e falhou depois? Não é a rede.
