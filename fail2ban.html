fail2ban: bloqueando quem erra

O fail2ban lê o log e bloqueia no firewall quem erra demais. Aqui você é bloqueado de verdade e se desbloqueia.

Você vai aprender
  • Ler um jail.local.
  • Ver um bloqueio acontecer.
  • Ver e desbloquear IPs.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

Bloqueando quem erra demais

O fail2ban lê os logs, conta as falhas de cada IP e, passando do limite, bloqueia esse IP no firewall por um tempo. Ele é útil sobretudo enquanto a senha ainda está ligada, mas também limpa o barulho dos robôs.

sudo apt install fail2ban
sudo systemctl enable --now fail2ban

1. A regra do laboratório

A configuração sua vai em /etc/fail2ban/jail.local (o jail.conf é do pacote e não se mexe). A do laboratório:

$ cat /etc/fail2ban/jail.local
[sshd]
enabled = true
backend = polling
logpath = /var/log/auth.log
maxretry = 3   « 3 falhas...
findtime = 10m   « ...em 10 minutos...
bantime = 10m   « ...e o IP fica 10 minutos bloqueado
$
backend

No laboratório o fail2ban lê o arquivo /var/log/auth.log (backend = polling). Num Debian 13 com systemd, o pacote já vem com backend = systemd e lê o journal; aí basta o enabled = true.

2. Errando a senha

Do notebook, sem a chave, três senhas erradas seguidas:

$ ssh -o PubkeyAuthentication=no lab@servidor
lab@servidor's password: 
Permission denied, please try again.   « terceira falha
lab@servidor's password: 
Permission denied, please try again.
lab@servidor's password: 
lab@servidor: Permission denied (publickey,password).
$

Alguns segundos depois, nem a chave certa passa: o notebook está bloqueado.

$ ssh lab@servidor hostname
ssh: connect to host servidor port 22: Connection refused   « o firewall recusou antes do sshd
$

3. Vendo e desbloqueando, no servidor

$ sudo fail2ban-client status sshd
Status for the jail: sshd
|- Filter
|  |- Currently failed:	0
|  |- Total failed:	3
|  `- File list:	/var/log/auth.log
`- Actions
   |- Currently banned:	1
   |- Total banned:	1
   `- Banned IP list:	192.168.0.10   « os IPs bloqueados agora
$ sudo fail2ban-client set sshd unbanip 192.168.0.10
1
$
$ ssh lab@servidor hostname
servidor   « liberado de novo
$
Não bloqueie a si mesmo

Em jail.local, a linha ignoreip = 127.0.0.1/8 192.168.0.0/24 (na seção [DEFAULT]) faz o fail2ban nunca bloquear esses endereços. Ponha ali o IP de onde você trabalha.

Quando dá errado

O fail2ban não está rodando

Sem o serviço, o fail2ban-client não tem com quem falar:

$ sudo fail2ban-client status
2026-11-21 12:03:35,539 fail2ban                [54]: ERROR   Failed to access socket path: /var/run/fail2ban/fail2ban.sock. Is fail2ban running?
$

Ligue o serviço (sudo systemctl enable --now fail2ban) e confira com sudo fail2ban-client status.
