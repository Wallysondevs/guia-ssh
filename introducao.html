O que é SSH

O SSH abre um terminal seguro em outro computador. Esta aula mostra o que ele faz, quem é cliente e quem é servidor, e o formato do comando.

Você vai aprender
  • O que é SSH e por que ele é seguro.
  • A diferença entre o cliente ssh e o servidor sshd.
  • O formato ssh usuario@computador comando.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: um terminal em outro computador

O SSH (Secure Shell, “casca segura”) é o jeito padrão de usar o terminal de outro computador pela rede. Você digita no seu teclado, e os comandos rodam lá, no servidor. Tudo o que vai e volta é criptografado: quem estiver no meio do caminho (o Wi-Fi do café, o provedor) não consegue ler as senhas nem os arquivos.

É com SSH que se administra quase todo servidor Linux do mundo, que se envia código para o GitHub e que se copiam arquivos entre máquinas. Uma provinha: do notebook da Ana, um comando que roda no servidor e devolve a resposta:

$ ssh lab@servidor hostname
servidor   « quem respondeu foi o servidor
$ ssh lab@servidor 'whoami; pwd'
lab
/home/lab   « a pasta do usuário lab, lá no servidor
$

Cliente e servidor

Toda conexão SSH tem dois lados:

LadoProgramaNeste guia
Cliente: de onde você se conectassh (e scp, sftp, ssh-keygen…)o notebook, com a usuária ana
Servidor: onde os comandos rodamsshd, o “daemon” que fica esperando conexões na porta 22o servidor, com o usuário lab

Os dois programas vêm do projeto OpenSSH, o mesmo no Linux, no macOS e no Windows 10/11. Veja a versão do seu cliente:

$ ssh -V
OpenSSH_10.0p2 Debian-7+deb13u4, OpenSSL 3.5.7 9 Jun 2026   « a versão usada em todo o guia
$
ssh
o cliente SSH.
-V
maiúsculo: mostra a versão e sai (o -v minúsculo é outra coisa, “verboso”, e aparece no Nível 5).

No servidor, o sshd fica rodando o tempo todo. No laboratório, o usuário lab pode conferir que ele está lá, ouvindo a porta 22:

$ ps -C sshd -o pid,cmd
    PID CMD
     45 sshd: /usr/sbin/sshd [listener] 0 of 10-100 startups
$

O formato do comando

ssh usuario@computador comando
  • usuario: a conta no servidor (pode ser diferente do seu usuário no notebook).
  • computador: o nome ou o IP do servidor (servidor, 192.168.0.20…).
  • comando (opcional): se você passar um comando, ele roda lá e o ssh volta. Sem comando, você entra numa sessão no servidor, como na próxima aula.

Quando dá errado

Nome errado

Se o nome do computador estiver errado, o ssh nem chega a tentar conectar. Na coleta, digitamos “servidr”:

$ ssh lab@servidr hostname
ssh: Could not resolve hostname servidr: Temporary failure in name resolution
$

“Could not resolve hostname” quer dizer: não sei que computador é esse. Confira o nome ou use o IP.
