known_hosts e fingerprints

O known_hosts é a agenda de servidores em que você já confiou. Esta aula mostra como ler, conferir e limpar essa agenda.

Você vai aprender
  • Procurar e apagar entradas com ssh-keygen -F e -R.
  • Conferir o fingerprint no servidor.
  • Ler a chave de um servidor com ssh-keyscan.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: a agenda de servidores conhecidos

Cada servidor SSH tem um par de chaves de host, criado quando o openssh-server é instalado. Quando você aceita a chave na primeira conexão, o ssh anota no arquivo ~/.ssh/known_hosts: “este nome tem esta chave”. Nas próximas vezes, ele confere. Se a chave mudar, o ssh se recusa a conectar, porque alguém pode estar fingindo ser o seu servidor (o ataque “homem do meio”).

No Debian e no Ubuntu os nomes ficam embaralhados (|1|…), para que ninguém descubra, lendo o arquivo, em que servidores você entra. Para procurar um servidor, use o ssh-keygen -F:

$ ssh-keygen -F servidor
# Host servidor found: line 1    « achou: linha 1 do arquivo
|1|21Md2Vf9fj8V9J9wAO9Chptabdo=|xFV1PbdgWQiuJin3f8FvJAH7Ncs= ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAINM6SGh5h96kOv8/Cg/bkoIlywT9DTgOpraeFBwMa4Ob
$

2. Conferir a impressão digital no servidor

Antes de digitar yes, compare o fingerprint com o do servidor. Quem tem acesso ao servidor (pelo console, por exemplo) vê assim:

$ ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
256 SHA256:J0mxzl4IvFNcHQshs1EWMr0nqvoP4JTeJSyl7UkanuE root@servidor (ED25519)   « tem de ser igual ao da pergunta
$
ssh-keygen -l
mostra o fingerprint de uma chave.
-f arquivo
qual chave.
ssh_host_ed25519_key.pub
a parte pública da chave de host do tipo ED25519.

Do lado do cliente, o ssh-keyscan pergunta a chave ao servidor sem fazer login. Junto com o ssh-keygen -lf -, mostra o mesmo fingerprint:

$ ssh-keyscan -t ed25519 servidor
# servidor:22 SSH-2.0-OpenSSH_10.0p2 Debian-7+deb13u4
servidor ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAINM6SGh5h96kOv8/Cg/bkoIlywT9DTgOpraeFBwMa4Ob
$ ssh-keyscan -t ed25519 servidor 2>/dev/null | ssh-keygen -lf -
256 SHA256:J0mxzl4IvFNcHQshs1EWMr0nqvoP4JTeJSyl7UkanuE servidor (ED25519)
$

As duas impressões digitais batem com a da pergunta da primeira conexão. Só confie se forem iguais.

3. Esquecer um servidor: ssh-keygen -R

Se o servidor foi reinstalado (e por isso ganhou chaves novas), apague a entrada antiga:

$ ssh-keygen -R servidor
# Host servidor found: line 1
/home/ana/.ssh/known_hosts updated.
Original contents retained as /home/ana/.ssh/known_hosts.old   « ele guarda uma cópia do arquivo antigo
$

Quando dá errado

Conferência rígida

Com StrictHostKeyChecking=yes (comum em scripts), o ssh não pergunta nada: se não conhece o servidor, recusa:

$ ssh -o StrictHostKeyChecking=yes lab@servidor hostname
No ED25519 host key is known for servidor and you have requested strict checking.
Host key verification failed.
$

Em scripts, prefira guardar a chave antes (com ssh-keyscan, conferindo o fingerprint) a desligar a conferência.

Referência rápida

Você digitaO que faz
ssh-keygen -F servidorprocura no known_hosts.
ssh-keygen -R servidorapaga do known_hosts.
ssh-keygen -lf arquivo.pubfingerprint de uma chave.
