O laboratório: notebook e servidor

Para praticar você precisa de um cliente e de um servidor. Pode ser dois computadores, uma máquina virtual ou um computador só.

Você vai aprender
  • Instalar o servidor SSH e criar o usuário de teste.
  • Dar um nome ao servidor no /etc/hosts.
  • Conferir a rede com getent e ping.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: um laboratório só seu

Para aprender SSH você precisa de dois computadores: um cliente e um servidor. Não precisa comprar nada nem alugar servidor na internet. Qualquer uma destas opções serve:

  • Dois computadores em casa (um notebook e um PC velho, um Raspberry Pi…), na mesma rede.
  • Uma máquina virtual (VirtualBox, GNOME Boxes) com Debian ou Ubuntu, fazendo o papel de servidor.
  • Um computador só: o servidor SSH roda no próprio Linux, e você se conecta em localhost. Tudo funciona igual, só que os dois lados são a mesma máquina.

Os exemplos do guia usam três computadores fictícios, todos numa rede de teste:

1. No servidor: instalar o sshd e criar o usuário lab

No computador que vai ser o servidor (Debian ou Ubuntu), instale o servidor SSH e crie o usuário de teste lab, com uma senha que você vai lembrar e permissão de usar sudo:

sudo apt install openssh-server
sudo adduser lab
sudo adduser lab sudo

Depois, entre como lab (sudo -iu lab) e crie os arquivos de exemplo com o script preparar-servidor.sh: bash preparar-servidor.sh. Ele cria o relatorio.txt e uma página em site/.

Descubra o IP do servidor com ip -br addr. No laboratório, o servidor tem duas placas de rede, uma para cada rede de teste:

$ hostname
servidor
$ ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128 
sv0@if2          UP             192.168.0.20/25    « o IP que o notebook usa
sv1@if2          UP             192.168.0.129/25 
$

2. No notebook: dar um nome ao servidor

Para escrever servidor em vez do IP, acrescente uma linha ao /etc/hosts do notebook, com o IP do seu servidor (se for o mesmo computador, use 127.0.0.1):

echo "192.168.0.20 servidor" | sudo tee -a /etc/hosts

E crie os arquivos de exemplo do lado do cliente com o preparar-notebook.sh: bash preparar-notebook.sh, na sua pasta pessoal. No laboratório, o notebook ficou assim:

O cliente já vem instalado

O ssh (pacote openssh-client) vem em quase todo Linux, no macOS e no Windows 10/11. Só o servidor precisa do openssh-server.

3. O resto do laboratório

Algumas aulas de túneis usam duas páginas de teste. Quando chegar lá, deixe-as rodando num terminal à parte:

cd ~/site && python3 -m http.server -b 127.0.0.1 8080     # no servidor, como lab
cd ~/site && python3 -m http.server -b 127.0.0.1 3000     # no notebook, como você

A máquina interno é opcional. Sem ela, as aulas mostram como fazer o mesmo com o próprio servidor.

Quando dá errado

O servidor SSH não está rodando

Se o openssh-server não estiver instalado, ou o serviço estiver parado, a conexão é recusada na hora. Na coleta, paramos o sshd de propósito:

$ ssh lab@servidor
ssh: connect to host servidor port 22: Connection refused
$

“Connection refused”: o computador existe e respondeu, mas ninguém atende na porta 22. No servidor, confira com sudo systemctl status ssh.
