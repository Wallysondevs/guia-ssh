Projeto: túnel para a wiki

Um site que só a rede interna enxerga, aberto no notebook com um comando.

Você vai aprender
  • Juntar ProxyJump e LocalForward.
  • Abrir e fechar o túnel.
  • Entender o caminho.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

O projeto

A wiki da empresa roda na máquina interno, que só a rede do servidor enxerga. O objetivo: abrir a wiki no navegador do notebook com um comando, pulando pelo servidor e com um túnel, tudo guardado no config.

1. O ponto de partida

$ curl -sS --max-time 3 http://192.168.0.130/
curl: (7) Failed to connect to 192.168.0.130 port 80 after 0 ms: Could not connect to server
$ ssh interno 'curl -s http://localhost/'
<h1>Wiki interna</h1><p>Só a rede interna enxerga esta página.</p>   « lá dentro ela existe
$

2. O bloco no config

$ printf 'Host wiki\n    HostName 192.168.0.130\n    User lab\n    ProxyJump servidor\n    LocalForward 8090 localhost:80\n    ExitOnForwardFailure yes\n' >> ~/.ssh/config
$ ssh -G wiki | grep -E '^(hostname|proxyjump|localforward) '
hostname 192.168.0.130
localforward 8090 [localhost]:80
proxyjump servidor
$

3. Abrindo, usando e fechando

$ ssh -f -N wiki
$ curl -s http://localhost:8090/
<h1>Wiki interna</h1><p>Só a rede interna enxerga esta página.</p>   « no notebook, pela porta 8090
$ pgrep -a ssh
55 ssh -W [192.168.0.130]:22 servidor
56 ssh -f -N wiki
$ pkill -f 'ssh -f -N wiki'
$

O segundo processo, ssh -W, é o salto pelo servidor que o ProxyJump abriu sozinho; ele termina junto com o túnel. No navegador, http://localhost:8090. O caminho: notebook → (SSH) → servidor → (SSH) → interno → wiki. Os dois trechos da rede vão criptografados.

Quando dá errado

Abriu duas vezes

Com ExitOnForwardFailure, o segundo túnel na mesma porta desiste em vez de ficar conectado à toa:

$ printf 'Host wiki\n    HostName 192.168.0.130\n    User lab\n    ProxyJump servidor\n    LocalForward 8090 localhost:80\n    ExitOnForwardFailure yes\n' >> ~/.ssh/config
$ ssh -f -N wiki
$ ssh -f -N wiki; echo "código: $?"
bind [127.0.0.1]:8090: Address already in use
channel_setup_fwd_listener_tcpip: cannot listen to port: 8090
Could not request local forwarding.
código: 255
$

Feche o primeiro (pkill -f 'ssh -f -N wiki') ou use outra porta.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: abra um túnel até a wiki da máquina interno e leia a página no notebook.



ssh -f -N -L 8090:localhost:80 interno && curl -s http://localhost:8090/

<h1>Wiki interna</h1><p>Só a rede interna enxerga esta página.</p>

Missão: leia a wiki pulando pelo servidor, sem túnel, rodando o curl lá dentro.



ssh -J servidor lab@192.168.0.130 'curl -s http://localhost/'

<h1>Wiki interna</h1><p>Só a rede interna enxerga esta página.</p>

Resumo

  • Tudo num bloco do config.
  • O destino do LocalForward é visto pelo último salto.
  • Feche o que não usa.
