Saltos com ProxyJump

O -J entra num servidor através de outro, com a sua chave e sem expor o agente.

Você vai aprender
  • Pular com -J.
  • Guardar o salto com ProxyJump.
  • A pergunta do fingerprint do destino.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: pular de máquina em máquina

Em muitas empresas, os servidores internos não aceitam conexão de fora: primeiro se entra num servidor de entrada (o “bastion”) e, dele, nos outros. O ProxyJump (-J) faz os dois saltos num comando só, e a autenticação no destino é feita pelo notebook, com a chave do notebook. Nada fica guardado no servidor do meio, e o agente não é exposto (ao contrário do -A).

1. Sem o salto, não chega

$ ssh lab@interno hostname
ssh: Could not resolve hostname interno: Temporary failure in name resolution
$ ssh -o ConnectTimeout=3 lab@192.168.0.130 hostname
ssh: connect to host 192.168.0.130 port 22: Network is unreachable
$

2. Com -J

$ ssh -J lab@servidor lab@192.168.0.130 hostname
interno   « chegou ao interno, passando pelo servidor
$ ssh -J lab@servidor lab@192.168.0.130 'ip -br addr'
lo               UNKNOWN        127.0.0.1/8 ::1/128 
in0@if3          UP             192.168.0.130/25 
$
-J lab@servidor
o salto: primeiro conecta aqui.
lab@192.168.0.130
o destino final, visto pelo servidor.

Dá para encadear saltos com vírgula: -J lab@a,lab@b destino.

3. No config: ProxyJump

$ cat ~/.ssh/config
Host servidor
    HostName 192.168.0.20
    User lab

Host interno
    HostName 192.168.0.130
    User lab
    ProxyJump servidor   « o salto, guardado no config
$ ssh interno hostname
interno
$ ssh -G interno | grep -i '^proxyjump'
proxyjump servidor
$ scp notas.txt interno:
notas.txt                                                         100%   53   174.8KB/s   00:00    
$ ssh interno ls
notas.txt
wiki
$

Com o bloco no config, ssh, scp, sftp e rsync pulam sozinhos.

Quando dá errado

A pergunta do fingerprint, para o destino

Cada máquina tem a sua chave de host. Na primeira vez no interno, o notebook pergunta por ela (o “no hostip for proxy command” é normal: quem conectou foi o servidor do meio):

$ ssh -J lab@servidor lab@192.168.0.130 hostname
The authenticity of host '192.168.0.130 (<no hostip for proxy command>)' can't be established.
ED25519 key fingerprint is SHA256:lbdIgm8/vYGYCdvOnY5COUJZ4pDV5o5pi9/TE3kHRRE.
This host key is known by the following other names/addresses:
    ~/.ssh/known_hosts:3: [hashed name]
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Warning: Permanently added '192.168.0.130' (ED25519) to the list of known hosts.
interno
$

Confira o fingerprint no próprio interno (ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub) e responda yes.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: pule pelo servidor até o IP dele mesmo (dá para treinar o -J com uma máquina só; troque pelo IP do seu servidor).



ssh -J lab@servidor lab@192.168.0.20 'echo salto ok'

salto ok

Missão: depois de criar o bloco Host interno com ProxyJump, confira com ssh -G.



ssh -G interno | grep -i '^proxyjump'

proxyjump servidor

Resumo

  • O -J autentica no destino a partir do notebook.
  • Funciona com scp, sftp e rsync.
  • Prefira -J a -A.
