Trabalhando no servidor

Dentro da sessão, tudo roda no servidor. Esta aula ensina a não se perder e a sair de uma conexão travada.

Você vai aprender
  • Ler o prompt para saber onde está.
  • Usar sudo no servidor.
  • Os escapes ~? e ~..

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: trabalhar lá dentro

Numa sessão SSH, o prompt avisa onde você está: ana@notebook é o seu computador; lab@servidor é o servidor. Parece óbvio, mas apagar arquivos no computador errado é o erro mais comum de quem começa. Olhe o prompt antes de cada comando importante.

1. Uma sessão de trabalho

$ ssh lab@servidor

Servidor de laboratório do Guia SSH. Tudo aqui é de teste.

lab@servidor:~$ pwd
/home/lab
lab@servidor:~$ ls -l
total 8
-rw-r--r-- 1 lab lab   47 nov 21 12:00 relatorio.txt

lab@servidor:~$ cat relatorio.txt

lab@servidor:~$ sudo whoami   « o sudo no servidor vale para o servidor

lab@servidor:~$ exit
sair

$

Comandos de administração, como sudo apt update, funcionam igual: rodam no servidor, com os privilégios do usuário lab de lá.

2. As teclas de escape do ssh: ~? e ~.

O cliente ssh tem atalhos próprios, que começam com ~ logo depois de um Enter. O ~? mostra a lista:

$ ssh lab@servidor

Servidor de laboratório do Guia SSH. Tudo aqui é de teste.

lab@servidor:~$ 
lab@servidor:~$ ~?
Supported escape sequences:
 ~.   - terminate connection (and any multiplexed sessions)   « derruba a conexão na hora
 ~B   - send a BREAK to the remote system
 ~R   - request rekey
 ~V/v - decrease/increase verbosity (LogLevel)
 ~^Z  - suspend ssh
 ~#   - list forwarded connections
 ~&   - background ssh (when waiting for connections to terminate)
 ~?   - this message
 ~~   - send the escape character by typing it twice
(Note that escapes are only recognized immediately after newline.)
exit
sair
Connection to servidor closed.
$

O mais útil é o ~.: quando a rede cai e a sessão congela, ele fecha a conexão travada sem você ter de fechar o terminal:

$ ssh lab@servidor

Servidor de laboratório do Guia SSH. Tudo aqui é de teste.

lab@servidor:~$ 
lab@servidor:~$ Connection to servidor closed.   « o ssh fechou a conexão
$

Quando dá errado

O programa não existe no servidor

Cada computador tem os seus programas. O htop existe no notebook? Não importa: o comando roda no servidor, e lá ele não foi instalado:

$ ssh lab@servidor htop
bash: linha 1: htop: comando não encontrado
$

A mensagem vem do Bash do servidor (“linha 1” é a do comando que o ssh mandou). Instale lá com sudo apt install htop, ou use outro comando.
