Config: curingas, ordem e Include

Com vários servidores, o config precisa de regras gerais. Esta aula mostra os curingas, a ordem e o Include.

Você vai aprender
  • Usar Host * e vários nomes num bloco.
  • Entender que o primeiro valor vence.
  • Separar o config com Include.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: regras para muitos servidores

O config fica mais poderoso com três recursos: curingas (Host *), a regra de “o primeiro valor vence” e o Include, que junta vários arquivos.

1. Curingas e vários nomes

Host * vale para todos os servidores; Host srv servidor dá dois nomes ao mesmo bloco. O ServerAliveInterval 60 manda um “sinal de vida” a cada 60 segundos, o que evita a queda de conexões paradas:

$ printf 'Host srv servidor\n    HostName 192.168.0.20\n    User lab\n\nHost *\n    ServerAliveInterval 60\n' > ~/.ssh/config
$ ssh -G srv | grep -E '^(user|serveraliveinterval) '
user lab
serveraliveinterval 60
$ ssh -G servidor | grep -E '^(user|serveraliveinterval) '
user lab
serveraliveinterval 60
$

2. O primeiro valor vence

O ssh lê o arquivo de cima para baixo e fica com o primeiro valor de cada opção. Por isso o Host * vai no fim, como padrão. O -F lê outro arquivo no lugar do config:

$ printf 'Host srv\n    User lab\nHost *\n    User ana\n' > certo.conf
$ printf 'Host *\n    User ana\nHost srv\n    User lab\n' > errado.conf
$ ssh -F certo.conf -G srv | grep '^user '
user lab   « o bloco srv veio antes
$ ssh -F errado.conf -G srv | grep '^user '
user ana   « o Host * veio antes e ganhou
$

3. Separar em arquivos: Include

Com muitos servidores, separe: um arquivo para o trabalho, outro para casa. O Include precisa ficar no começo do config:

$ mkdir -p ~/.ssh/config.d && printf 'Host wiki\n    HostName 192.168.0.130\n    User lab\n' > ~/.ssh/config.d/trabalho.conf && sed -i '1i Include config.d/*.conf' ~/.ssh/config
$ head -3 ~/.ssh/config
Include config.d/*.conf
Host servidor
    HostName 192.168.0.20
$ ssh -G wiki | grep -E '^(hostname|user) '
user lab
hostname 192.168.0.130
$

Quando dá errado

Permissão do config

O config também precisa ser só seu. Com escrita para outros, o ssh se recusa a ler:

$ chmod 666 ~/.ssh/config
$ ssh servidor hostname
Bad owner or permissions on /home/ana/.ssh/config
$

Corrija com chmod 600 ~/.ssh/config.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: mostre o valor do ServerAliveInterval que o ssh usaria para o servidor.



ssh -G servidor | grep -i '^serveraliveinterval'

serveraliveinterval 0

Missão: mude o ServerAliveInterval só nesta conexão (com -o) e confira com -G.



ssh -o ServerAliveInterval=30 -G servidor | grep -i '^serveraliveinterval'

serveraliveinterval 30

Resumo
