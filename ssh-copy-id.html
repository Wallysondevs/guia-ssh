Instalando a chave: ssh-copy-id

Com a chave criada, falta levar a parte pública ao servidor. O ssh-copy-id faz isso com uma última senha.

Você vai aprender
  • Instalar a chave com ssh-copy-id.
  • Ver o resultado no servidor.
  • Escolher a chave com -i.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: instalar a chave pública no servidor

O ssh-copy-id faz login com a senha uma última vez e acrescenta a sua chave pública ao ~/.ssh/authorized_keys do servidor, criando a pasta e acertando as permissões. Daí em diante, entra-se com a chave.

1. Copiar a chave

$ ssh-copy-id lab@servidor
/usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "/home/ana/.ssh/id_ed25519.pub"   « qual chave ele vai instalar
/usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s), to filter out any that are already installed
/usr/bin/ssh-copy-id: INFO: 1 key(s) remain to be installed -- if you are prompted now it is to install the new keys
lab@servidor's password:    « a última vez que a senha é pedida

Number of key(s) added: 1   « instalada

Now try logging into the machine, with: "ssh 'lab@servidor'"   « entrou sem senha
and check to make sure that only the key(s) you wanted were added.
$ ssh lab@servidor hostname
servidor
$

No servidor, o ssh-copy-id deixou a pasta e o arquivo com as permissões certas (700 e 600):

$ ls -la ~/.ssh
total 12
drwx------ 2 lab lab 4096 nov 21 12:01 .
drwxr-xr-x 4 lab lab 4096 nov 21 12:01 ..
-rw------- 1 lab lab   94 nov 21 12:01 authorized_keys
$ cat ~/.ssh/authorized_keys
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEhUpv1BK1coguxPjJIpUIlNaF5MdZXnkYskI28ZKD0p ana@notebook
$

2. Rodar de novo não duplica

$ ssh-copy-id lab@servidor
/usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "/home/ana/.ssh/id_ed25519.pub"
/usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s), to filter out any that are already installed

/usr/bin/ssh-copy-id: WARNING: All keys were skipped because they already exist on the remote system.   « a chave já estava lá
		(if you think this is a mistake, you may want to use -f option)
$

3. Escolher qual chave instalar: -i

Com várias chaves, o -i diz qual instalar. Como a chave padrão já estava no servidor, nem precisou de senha:

$ ssh-copy-id -i ~/.ssh/servidor_lab.pub lab@servidor
/usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "/home/ana/.ssh/servidor_lab.pub"
/usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s), to filter out any that are already installed
/usr/bin/ssh-copy-id: INFO: 1 key(s) remain to be installed -- if you are prompted now it is to install the new keys

Number of key(s) added: 1

Now try logging into the machine, with: "ssh -i /home/ana/.ssh/servidor_lab 'lab@servidor'"
and check to make sure that only the key(s) you wanted were added.
$ ssh -i ~/.ssh/servidor_lab lab@servidor 'tail -1 ~/.ssh/authorized_keys'
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIBMb+0E2Yg6UogPlI99S0FwsS4cAPW7FZcMs4qj1tGXQ chave do lab   « a chave nova, no fim do arquivo
$

Quando dá errado

Ainda não existe chave

Sem chave em ~/.ssh, o ssh-copy-id não tem o que copiar:

$ ssh-copy-id lab@servidor
/usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: 
/usr/bin/ssh-copy-id: ERROR: No identities found
$

Gere a chave antes, com ssh-keygen -t ed25519.
