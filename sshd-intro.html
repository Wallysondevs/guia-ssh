O servidor sshd

Do outro lado de cada conexão está o sshd. Esta aula mostra onde ele mora e como ler a configuração dele.

Você vai aprender
  • Achar o processo e a porta do sshd.
  • Diferenciar sshd_config de ssh_config.
  • Ler a configuração final com sshd -T.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

Quem atende do outro lado

Até aqui você usou o cliente (ssh, scp, sftp). Do outro lado está o servidor, o programa sshd (o “d” é de daemon, um programa que fica rodando em segundo plano). No Debian e no Ubuntu ele vem no pacote openssh-server e o serviço se chama ssh.

sudo apt install openssh-server     # instala o servidor
sudo systemctl status ssh           # está rodando?

1. O processo e a porta

Nesta aula os comandos rodam no servidor, como lab:

$ ps -C sshd -o pid,cmd
    PID CMD
     45 sshd: /usr/sbin/sshd [listener] 0 of 10-100 startups   « o processo que espera conexões
$ sudo ss -ltnp | grep sshd
LISTEN 0      128          0.0.0.0:22        0.0.0.0:*    users:(("sshd",pid=45,fd=6))      « a porta padrão do SSH
LISTEN 0      128             [::]:22           [::]:*    users:(("sshd",pid=45,fd=7))   
$

2. Os arquivos

$ ls /etc/ssh
moduli	      sshd_config	  ssh_host_ecdsa_key.pub    ssh_host_rsa_key   « a configuração do servidor
ssh_config    sshd_config.d	  ssh_host_ed25519_key	    ssh_host_rsa_key.pub   « a do cliente (sem o d)
ssh_config.d  ssh_host_ecdsa_key  ssh_host_ed25519_key.pub   « a chave do servidor, a do fingerprint
$

Cuidado com a letra: sshd_config é o servidor; ssh_config é o cliente. O arquivo principal quase não tem nada ativo; o resto são comentários com os valores padrão:

$ grep -Ev '^(#|$)' /etc/ssh/sshd_config
Include /etc/ssh/sshd_config.d/*.conf   « lê os arquivos da pasta sshd_config.d primeiro
KbdInteractiveAuthentication no
UsePAM yes
X11Forwarding yes
PrintMotd no
AcceptEnv LANG LC_* COLORTERM NO_COLOR
Subsystem	sftp	/usr/lib/openssh/sftp-server
$
A primeira vez vale

No sshd_config, para a maioria das opções, vale o primeiro valor que o sshd encontra. Como o Include está no topo, um arquivo seu em /etc/ssh/sshd_config.d/ ganha do resto. É lá que as próximas aulas mexem, sem tocar no arquivo original.

3. O que está valendo de verdade

O sshd -T mostra a configuração final, já com os padrões e os arquivos incluídos, tudo em minúsculas:

$ sudo sshd -T | grep -E '^(port|passwordauthentication|pubkeyauthentication|permitrootlogin) '
port 22
permitrootlogin without-password   « root só entra com chave
pubkeyauthentication yes
passwordauthentication yes   « senha ainda aceita
$

Quando dá errado

Sem sudo

O programa sshd fica em /usr/sbin, pasta que não está no PATH de um usuário comum no Debian:

$ sshd -T | head -n 3
bash: sshd: comando não encontrado
$

Use sudo sshd -T: o sudo procura também em /usr/sbin, e o sshd -T precisa ler as chaves privadas do servidor (ssh_host_*_key, sem .pub), que só o root lê.
