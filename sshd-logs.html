Os logs do servidor

Cada tentativa de login deixa rastro. Esta aula mostra onde e como ler.

Você vai aprender
  • Achar o log do sshd.
  • Ler linhas de login aceito e recusado.
  • Contar tentativas por IP.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

Onde o sshd conta o que aconteceu

Cada conexão, aceita ou recusada, vira uma linha de log no servidor. No Debian e no Ubuntu com systemd, o jeito mais direto é o journalctl; onde existe o arquivo /var/log/auth.log, ele tem as mesmas linhas:

sudo journalctl -u ssh -n 20        # as últimas 20 linhas do serviço ssh
sudo journalctl -u ssh -f           # acompanha ao vivo (Ctrl+C sai)

O laboratório grava em /var/log/auth.log. Antes da caixa, a ana entrou uma vez com a chave e alguém tentou o usuário teste, que não existe:

1. As linhas do sshd

$ sudo grep -E 'Accepte[d]|Invalid use[r]|session opene[d] for user lab' /var/log/auth.log
2026-11-21T12:03:12.403226-03:00 servidor sshd-session[49]: Accepted publickey for lab from 192.168.0.10 port 49770 ssh2: ED25519 SHA256:1wgPtPehvxJHxq1qIDo4s7Eu1nZObhihxhAUBwbUHkU   « entrou com chave
2026-11-21T12:03:12.404378-03:00 servidor sshd-session[49]: pam_unix(sshd:session): session opened for user lab(uid=1002) by lab(uid=0)
2026-11-21T12:03:12.477480-03:00 servidor sshd-session[56]: Invalid user teste from 192.168.0.10 port 49780   « usuário que não existe
$
Por que os colchetes no grep?

O próprio sudo também escreve no auth.log o comando que rodou, com o texto do grep. Accepte[d] casa com “Accepted”, mas não com a linha do sudo, que tem o texto Accepte[d] com os colchetes.

2. Contando

$ sudo grep -c 'Accepted publicke[y]' /var/log/auth.log
1
$ sudo grep 'Invalid use[r]' /var/log/auth.log | awk '{print $(NF-2)}' | sort | uniq -c
      1 192.168.0.10
$

Num servidor de verdade, essa segunda linha costuma mostrar centenas de IPs desconhecidos por dia. É o motivo do fail2ban.

Quando dá errado

Sem permissão

O log de autenticação é só do root e do grupo adm:

$ tail -n 2 /var/log/auth.log
tail: não foi possível abrir '/var/log/auth.log' para leitura: Permissão negada
$ ls -l /var/log/auth.log
-rw-r----- 1 root adm 173 nov 21 12:03 /var/log/auth.log
$

Use sudo, ou peça para entrar no grupo adm.
