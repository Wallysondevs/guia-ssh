Desligando a senha

Com a chave funcionando, o servidor pode parar de aceitar senha. Os robôs ficam do lado de fora.

Você vai aprender
  • Criar um arquivo em sshd_config.d.
  • Testar com sshd -t e recarregar.
  • Provar com PubkeyAuthentication=no.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

Por que desligar a senha

Todo servidor ligado na internet recebe, o dia inteiro, robôs tentando senhas como 123456 e admin. Com a chave funcionando (Nível 2), dá para fechar essa porta: o servidor passa a aceitar só chave.

Deixe uma sessão aberta

Antes de mexer no sshd de um servidor remoto, deixe um terminal conectado e teste a mudança em outro. Se a configuração nova trancar você do lado de fora, a sessão antiga ainda está lá para desfazer.

1. Confira que a chave funciona

Antes de tudo, no notebook: se esta linha pedir senha, pare e volte para a aula do ssh-copy-id.

$ ssh -o PasswordAuthentication=no lab@servidor hostname
servidor   « entrou só com a chave
$

2. O arquivo novo, no servidor

$ echo 'PasswordAuthentication no' | sudo tee /etc/ssh/sshd_config.d/10-sem-senha.conf
PasswordAuthentication no
$ sudo sshd -t && sudo kill -HUP "$(cat /run/sshd.pid)"
$ sudo sshd -T | grep '^passwordauthentication'
passwordauthentication no   « agora vale
$
Recarregar sem derrubar ninguém

Num servidor comum, depois de mexer na configuração rode sudo sshd -t (confere o arquivo) e sudo systemctl reload ssh. O laboratório do guia não usa o systemd, então manda o mesmo aviso direto ao processo: sudo kill -HUP "$(cat /run/sshd.pid)". As sessões abertas continuam vivas.

3. Testando do notebook

Com -o PubkeyAuthentication=no o cliente finge não ter chave, como um robô faria:

$ ssh -o PubkeyAuthentication=no lab@servidor
lab@servidor: Permission denied (publickey).   « nem pergunta a senha: só chave
$ ssh lab@servidor hostname
servidor   « com a chave, tudo igual
$

Repare que a lista entre parênteses mudou: antes era (publickey,password), agora é só (publickey).

Quando dá errado

Erro de digitação

Uma letra errada no nome da opção e o sshd recusa o arquivo. Por isso o sshd -t vem antes de recarregar:

$ echo 'PasswordAuthentcation no' | sudo tee /etc/ssh/sshd_config.d/10-sem-senha.conf
PasswordAuthentcation no
$ sudo sshd -t && sudo kill -HUP "$(cat /run/sshd.pid)"
/etc/ssh/sshd_config.d/10-sem-senha.conf: line 1: Bad configuration option: PasswordAuthentcation
/etc/ssh/sshd_config.d/10-sem-senha.conf: terminating, 1 bad configuration options
$

O && fez o recarregamento não acontecer: o sshd continua com a configuração antiga, que funciona. Corrija o nome e rode de novo.
