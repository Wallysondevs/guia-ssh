Túneis no config

Túnel de todo dia vira um apelido. Esta aula mostra como abrir, listar e fechar.

Você vai aprender
  • Escrever LocalForward no config.
  • Ver e fechar túneis com pgrep e pkill.
  • Usar ExitOnForwardFailure.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: túneis com nome

Túnel que você usa todo dia merece um bloco no config. As opções equivalentes: LocalForward (-L), RemoteForward (-R) e DynamicForward (-D). E o ExitOnForwardFailure yes faz o ssh desistir se não conseguir abrir o túnel, em vez de ficar conectado sem ele.

Host painel
    HostName 192.168.0.20
    User lab
    LocalForward 8080 localhost:8080
    ExitOnForwardFailure yes

1. Abrir pelo apelido

$ printf 'Host painel\n    HostName 192.168.0.20\n    User lab\n    LocalForward 8080 localhost:8080\n    ExitOnForwardFailure yes\n' >> ~/.ssh/config
$ ssh -f -N painel
$ curl -s http://localhost:8080/
<h1>Painel do servidor</h1><p>Esta página só abre no próprio servidor (127.0.0.1:8080).</p>
$ pgrep -a ssh
46 ssh -f -N painel   « o processo do túnel
$

2. Fechar

$ printf 'Host painel\n    HostName 192.168.0.20\n    User lab\n    LocalForward 8080 localhost:8080\n    ExitOnForwardFailure yes\n' >> ~/.ssh/config
$ ssh -f -N painel
$ pkill -f 'ssh -f -N painel'
$ pgrep -a ssh
$ curl -sS http://localhost:8080/
curl: (7) Failed to connect to localhost port 8080 after 0 ms: Could not connect to server
$

3. O ExitOnForwardFailure em ação

Com a porta 8080 já ocupada por um túnel, o segundo ssh desiste e devolve erro (código 255), em vez de fingir que deu certo:

$ printf 'Host painel\n    HostName 192.168.0.20\n    User lab\n    LocalForward 8080 localhost:8080\n    ExitOnForwardFailure yes\n' >> ~/.ssh/config
$ ssh -f -N painel
$ ssh -f -N painel; echo "código: $?"
bind [127.0.0.1]:8080: Address already in use
channel_setup_fwd_listener_tcpip: cannot listen to port: 8080
Could not request local forwarding.
código: 255   « desistiu: nada de conexão sem túnel
$

Quando dá errado

Túnel aberto e esquecido

Túneis com -f ficam abertos até você fechar, mesmo fechando o terminal. Antes de abrir de novo, veja o que já existe:

$ ssh -f -N -L 8080:localhost:8080 lab@servidor
$ ssh -f -N -D 1080 lab@servidor
$ pgrep -a ssh
46 ssh -f -N -L 8080:localhost:8080 lab@servidor
48 ssh -f -N -D 1080 lab@servidor
$

Feche o que não usa com kill e o número do processo, ou pkill -f com um pedaço do comando.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: abra um túnel em segundo plano e mostre o processo dele.



ssh -f -N -L 8080:localhost:8080 lab@servidor && pgrep -a ssh

46 ssh -f -N -L 8080:localhost:8080 lab@servidor

Missão: tente abrir um túnel na porta 3000 do notebook (já usada pelo seu site) com ExitOnForwardFailure.



ssh -o ExitOnForwardFailure=yes -f -N -L 3000:localhost:8080 lab@servidor

bind [127.0.0.1]:3000: Address already in use

Resumo

  • Túnel com nome: ssh -f -N apelido.
  • ExitOnForwardFailure evita conexão sem túnel.
  • Feche o que não usa.
