Proxy SOCKS: túnel dinâmico (-D)

Com -D, qualquer programa que saiba usar proxy SOCKS passa a sair pelo servidor.

Você vai aprender
  • Abrir um proxy com -D.
  • Usar com curl --socks5-hostname.
  • Configurar o navegador.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: um proxy para tudo

O -L leva uma porta a um destino. O túnel dinâmico (-D) abre no notebook um proxy SOCKS: cada programa que usar o proxy diz aonde quer ir, e o servidor faz a conexão. É como se o notebook navegasse “de dentro” do servidor.

1. Abrir o proxy

$ ssh -f -N -D 1080 lab@servidor
$ curl -s --socks5-hostname localhost:1080 http://192.168.0.130/
<h1>Wiki interna</h1><p>Só a rede interna enxerga esta página.</p>   « a wiki, alcançada pelo servidor
$ curl -s --socks5-hostname localhost:1080 http://localhost:8080/
<h1>Painel do servidor</h1><p>Esta página só abre no próprio servidor (127.0.0.1:8080).</p>   « localhost aqui é o servidor
$ curl -s --socks5-hostname localhost:1080 http://interno/
<h1>Wiki interna</h1><p>Só a rede interna enxerga esta página.</p>
$
-D 1080
abre o proxy SOCKS na porta 1080 do notebook.
--socks5-hostname
manda o curl usar o proxy e deixar o servidor traduzir os nomes.

Repare na última linha: o nome interno só existe para o servidor, e funcionou porque o curl deixou o servidor resolver o nome.

No navegador

No Firefox: Configurações → Rede → Configurar conexão → SOCKS v5, host localhost, porta 1080, e marque “Proxy DNS ao usar SOCKS v5”. Enquanto o túnel estiver aberto, o navegador vê o que o servidor vê.

Quando dá errado

O nome resolvido no lugar errado

Com --socks5 (sem -hostname), quem traduz o nome é o notebook, que não conhece interno:

$ ssh -f -N -D 1080 lab@servidor
$ curl -sS --socks5 localhost:1080 http://interno/
curl: (97) Could not resolve proxy: localhost
$

Use --socks5-hostname no curl (ou “Proxy DNS” no navegador) para o servidor resolver os nomes. (A mensagem do curl fala em “proxy”, mas o nome que ele não conseguiu traduzir foi interno.)
