Túnel local (-L)

O -L traz para o seu computador uma porta que só existe dentro do servidor.

Você vai aprender
  • Abrir um túnel com -L.
  • Usar -f e -N.
  • Escolher a porta local.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: trazer uma porta do servidor para o notebook

O servidor tem um painel web que só escuta em 127.0.0.1:8080, ou seja, só abre de dentro do próprio servidor. É assim, de propósito, com muitos painéis e bancos de dados. Um túnel local (-L) abre uma porta no notebook e leva tudo o que chega nela, por dentro do SSH, até o servidor.

ssh -L porta_no_notebook:destino:porta_do_destino usuario@servidor

O destino é visto a partir do servidor: localhost ali quer dizer “o próprio servidor”.

1. Antes do túnel

$ curl -sS http://localhost:8080/
curl: (7) Failed to connect to localhost port 8080 after 0 ms: Could not connect to server   « no notebook, nada na porta 8080
$ ssh lab@servidor 'curl -s http://localhost:8080/'
<h1>Painel do servidor</h1><p>Esta página só abre no próprio servidor (127.0.0.1:8080).</p>   « no servidor, o painel responde
$

2. Abrindo o túnel

$ ssh -f -N -L 8080:localhost:8080 lab@servidor
$ curl -s http://localhost:8080/
<h1>Painel do servidor</h1><p>Esta página só abre no próprio servidor (127.0.0.1:8080).</p>   « o painel, aberto no notebook
$ ss -ltn | grep 8080
LISTEN 0      128        127.0.0.1:8080      0.0.0.0:*      « a porta do túnel, só no notebook
LISTEN 0      128            [::1]:8080         [::]:*   
$
-f e -N

-N: não roda comando nenhum, só mantém o túnel. -f: vai para o segundo plano depois de conectar, devolvendo o terminal. Para fechar, use pkill -f "ssh -f -N" (ou o kill com o número do processo).

No navegador do notebook, http://localhost:8080 abre o painel. A porta local não precisa ser igual à remota:

$ ssh -f -N -L 9000:localhost:8080 lab@servidor
$ curl -s http://localhost:9000/
<h1>Painel do servidor</h1><p>Esta página só abre no próprio servidor (127.0.0.1:8080).</p>
$
Só no notebook

Por padrão, a porta do túnel escuta só em 127.0.0.1: outras máquinas da sua rede não a enxergam. Mais seguro assim.

Quando dá errado

A porta já está em uso

Abrir o mesmo túnel duas vezes (ou numa porta que outro programa usa) não funciona. O ssh avisa, mas a conexão continua, sem túnel:

$ ssh -f -N -L 8080:localhost:8080 lab@servidor
$ ssh -f -N -L 8080:localhost:8080 lab@servidor
bind [127.0.0.1]:8080: Address already in use
channel_setup_fwd_listener_tcpip: cannot listen to port: 8080
Could not request local forwarding.
$

Escolha outra porta local, ou feche o túnel antigo. Em scripts, use -o ExitOnForwardFailure=yes, que faz o ssh desistir (aula Túneis no config).

Resumo

  • -L local:destino:porta.
  • O destino é visto pelo servidor.
  • A porta local escuta só em 127.0.0.1.
