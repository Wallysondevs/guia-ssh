Túnel remoto (-R)

O -R é o -L ao contrário: uma porta no servidor que leva ao seu computador.

Você vai aprender
  • Abrir um túnel com -R.
  • Ver a porta no servidor.
  • O que é o GatewayPorts.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: o contrário do -L

O túnel remoto (-R) abre uma porta no servidor que leva até o notebook. Serve para mostrar algo que roda no seu computador (um site em desenvolvimento, por exemplo) a partir do servidor, sem abrir nada no seu roteador.

ssh -R porta_no_servidor:destino:porta_do_destino usuario@servidor

Agora o destino é visto a partir do notebook. No laboratório, a Ana tem um site rodando no notebook, em 127.0.0.1:3000.

1. Abrindo o túnel remoto

$ curl -s http://localhost:3000/
<h1>Site da Ana</h1><p>Rodando no notebook (127.0.0.1:3000).</p>   « no notebook
$ ssh -f -N -R 9000:localhost:3000 lab@servidor
$ ssh lab@servidor 'curl -s http://localhost:9000/'
<h1>Site da Ana</h1><p>Rodando no notebook (127.0.0.1:3000).</p>
$

A última linha rodou no servidor e trouxe a página do notebook.

2. Quem enxerga a porta

No servidor, a porta 9000 escuta só em 127.0.0.1: só quem já está dentro do servidor a usa. Para abrir para a rede do servidor, o administrador teria de ligar GatewayPorts no sshd_config (raramente uma boa ideia).

$ ssh -f -N -R 9000:localhost:3000 lab@servidor
$ ssh lab@servidor 'ss -ltn | grep 9000'
LISTEN 0      128        127.0.0.1:9000      0.0.0.0:*      « só dentro do servidor
LISTEN 0      128            [::1]:9000         [::]:*   
$

Quando dá errado

A porta do servidor está ocupada

Se a porta já estiver em uso no servidor (aqui, por um túnel aberto antes), o servidor recusa e o ssh só avisa:

$ ssh -f -N -R 9000:localhost:3000 lab@servidor
$ ssh -f -N -R 9000:localhost:3000 lab@servidor
$

Use outra porta no servidor. Lá, ss -ltn mostra o que já está ocupado.

Missões

Rode no seu laboratório (o seu notebook e o seu servidor de teste) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: com o seu site rodando na porta 3000, mostre-o a partir do servidor por um túnel remoto.

Missão: abra um túnel remoto na porta 9001 e mostre, no servidor, que ela está escutando.



ssh -f -N -R 9001:localhost:3000 lab@servidor && ssh lab@servidor "ss -ltn | grep ':9001 '"

LISTEN 0      128        127.0.0.1:9001      0.0.0.0:*

Resumo

  • -R servidor:destino:porta.
  • O destino é visto pelo notebook.
  • A porta escuta só em 127.0.0.1 do servidor.
