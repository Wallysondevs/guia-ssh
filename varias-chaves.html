Várias chaves

Com mais de uma chave, é preciso dizer ao ssh qual usar. Esta aula mostra como, e o erro clássico de quem tem chaves demais.

Você vai aprender
  • Escolher a chave com -i.
  • Ver a ordem das tentativas com -v.
  • Usar IdentitiesOnly.

Todas as saídas desta aula foram colhidas de verdade com o OpenSSH 10.0p2 no Linux (Debian 13, Bash 5.2, pt_BR.UTF-8), no laboratório do guia: o notebook (usuária ana, 192.168.0.10), o servidor (usuário lab, 192.168.0.20) e o interno (192.168.0.130, que só o servidor alcança). Antes de cada caixa o laboratório volta a um estado conhecido. As chaves e as impressões digitais que aparecem são de teste e já foram destruídas.

A ideia: uma chave para cada lugar

Muita gente tem várias chaves: uma do trabalho, uma do GitHub, uma do servidor de casa. O ssh tenta, em ordem, as chaves do agente e as chaves padrão (id_ed25519, id_rsa…). Para uma chave com outro nome, diga qual com -i.

1. Escolher a chave: -i

No servidor, desta vez, só a chave servidor_lab está instalada. A padrão não entra; com -i, entra:

$ ssh -o BatchMode=yes lab@servidor hostname
lab@servidor: Permission denied (publickey,password).   « a chave padrão não está no servidor
$ ssh -i ~/.ssh/servidor_lab lab@servidor hostname
servidor
$

(Na coleta, a cópia da chave para o servidor foi feita antes, por fora.)

$ ssh -v -i ~/.ssh/servidor_lab lab@servidor true 2>&1 | grep -E 'Will attempt key|Server accepts key'
debug1: Will attempt key: /home/ana/.ssh/servidor_lab ED25519 SHA256:6IhHnMXZlsA+WrffV2FLfHtjofkajESu1HR/cy11my0 explicit   « a do -i vem primeiro
debug1: Server accepts key: /home/ana/.ssh/servidor_lab ED25519 SHA256:6IhHnMXZlsA+WrffV2FLfHtjofkajESu1HR/cy11my0 explicit   « o servidor aceitou esta
$

2. Chaves demais: “Too many authentication failures”

O servidor aceita poucas tentativas por conexão (MaxAuthTries, 6 por padrão). Com muitas chaves no agente, o ssh oferece uma por uma e pode ser expulso antes de chegar à certa:

$ for i in 1 2 3 4 5 6; do ssh-keygen -q -t ed25519 -N '' -f ~/.ssh/k$i; done
$ eval "$(ssh-agent -s)" >/dev/null && ssh-add -q ~/.ssh/k1 ~/.ssh/k2 ~/.ssh/k3 ~/.ssh/k4 ~/.ssh/k5 ~/.ssh/k6
$ ssh lab@servidor hostname
Received disconnect from 192.168.0.20 port 22:2: Too many authentication failures   « esgotou as tentativas
Disconnected from 192.168.0.20 port 22
$ ssh -o IdentitiesOnly=yes -i ~/.ssh/id_ed25519 lab@servidor hostname
servidor   « com IdentitiesOnly, só a chave certa
$
-o IdentitiesOnly=yes
usa só as chaves indicadas com -i (ou no config), não todas as do agente.

Quando dá errado

-i com a chave pública

O -i recebe a chave privada (sem .pub). Com o .pub, o ssh tenta usá-lo como chave privada, reclama das permissões (um .pub é 644) e o ignora:

$ ssh -o BatchMode=yes -i ~/.ssh/servidor_lab.pub lab@servidor hostname
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for '/home/ana/.ssh/servidor_lab.pub' are too open.
It is required that your private key files are NOT accessible by others.
This private key will be ignored.
Load key "/home/ana/.ssh/servidor_lab.pub": bad permissions
lab@servidor: Permission denied (publickey,password).
$

Passe o arquivo sem .pub: -i ~/.ssh/servidor_lab.
